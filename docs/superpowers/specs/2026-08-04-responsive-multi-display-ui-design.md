# SmartTest 多显示器响应式 UI 设计

## 背景与目标

SmartTest 当前依赖 Qt/Windows 的 DPI 缩放，但主窗口和多个业务页面仍使用固定窗口尺寸、固定列宽或缺少正确层级的滚动兜底。在小屏、低可用逻辑分辨率或高 Windows 缩放比例下，内容会互相挤压、被截断且无法滚动；连接高分辨率外屏后恢复正常，证明问题是可用逻辑空间不足而非 QML 构建或字体资源差异。

本设计建立统一的“响应式重排 + 滚动兜底 + 多显示器窗口约束”。目标不是让不同显示器呈现相同物理大小，而是在不同屏幕尺寸、分辨率和 DPI 下保持字体清晰、布局不重叠、内容不截断、所有操作可访问。

## 范围

本次覆盖全部 SmartTest 业务入口及其公共业务组件：

- Main、Login、Home；
- Test Config、Run、Report；
- Tool；
- Redmine 登录、Workspace、Clone、详情；
- Jira、Jira Audit；
- Confluence Audit、Daily Report；
- Settings、Debug；
- 上述页面使用的业务弹窗、表单、详情、表格和日志布局。

FluentUI 纯演示页面不纳入本次范围。布局适配不得改变测试参数、运行、报告、认证、远程候选缓存或其他业务数据 owner。

## 方案选择

采用方案 C：响应式布局与滚动兜底。

不采用全局 `scale`：整体缩放会造成字体和点击区域过小、DPI 双重缩放、模糊及固有布局问题继续存在。也不采用仅增加滚动条：滚动只能保证访问，无法解决双栏、固定宽度表单和卡片在小屏上的拥挤。

数据流为：

```text
当前屏幕 availableGeometry
→ 约束窗口尺寸和位置
→ 导航扣除后的页面实际宽度
→ 选择统一布局档位
→ 页面重排
→ 内容仍超出时由明确 owner 提供滚动
```

## 公共架构

### ResponsiveMetrics

新增一个轻量公共响应式尺寸 owner，统一断点和安全尺寸，不拥有业务状态。页面根据自身实际内容宽度使用以下档位：

```text
compact：内容宽度 < 720
medium：720–1099
wide：≥ 1100
```

它提供 `compactLayout`、`mediumLayout`、`wideLayout`、`safeContentWidth` 和 `safeContentHeight` 等只读派生值。页面不得根据显示器品牌、物理英寸、具体分辨率或设备名写特例，也不得自行定义冲突断点。

布局档位依据页面视口，而不是物理屏幕：导航栏开合、窗口缩放、跨屏和 DPI 变化都会通过实际内容宽度自然更新布局。

### AdaptiveWindow

窗口级 owner 根据当前屏幕的 `availableGeometry` 计算初始尺寸、最小尺寸和合法位置：

```text
目标宽度  = min(设计宽度, 可用宽度 × 0.92)
目标高度  = min(设计高度, 可用高度 × 0.92)
```

具体行为：

- 大屏保留舒适设计尺寸，不无限放大；
- 小屏收敛到任务栏之外的可用范围；
- 动态最小尺寸不得大于当前屏幕可用尺寸；
- 旧保存尺寸或位置超出当前屏幕时先约束再显示；
- 窗口跨屏后重新检查边界和布局；
- 外屏拔出后移动到剩余屏幕可见区域；
- 屏幕信息尚未就绪时使用安全默认值，并在下一事件循环重算；
- 不覆盖 Windows DPI 设置，不手动缩放字体。

公共能力应复用 Qt/FluentUI 已有 Screen、窗口和布局机制。只有现有 owner 无法表达屏幕边界收敛时才新增最小 helper，不建立第二套窗口系统。

## 页面布局契约

### 普通表单页

页面使用单一纵向滚动 owner。wide/medium 下标签与输入框可左右排列；compact 下改为标签在上、输入框在下。错误提示跟随字段并增加高度，不覆盖相邻字段。

### 卡片与仪表盘页

使用响应式网格：wide 为 3–4 列，medium 为 2 列，compact 为 1 列。卡片宽度不得低于可读下限；空间不足时增加页面高度并纵向滚动，不减小字体。

### 主从与双栏页

wide/medium 使用左右双栏；compact 改为上下排列或明确的列表/详情切换。不得把两个区域压成不可读窄栏。

### 表格、日志与代码内容

标题、筛选和操作区随页面响应式重排；真正不可压缩的表格、日志或代码区域拥有局部滚动。表格可局部横向滚动，日志沿用现有日志组件滚动。同一区域不得出现两个方向相同的嵌套滚动。

### 弹窗

业务弹窗满足：

```text
width  ≤ 当前窗口内容宽度 × 90%
height ≤ 当前屏幕可用高度 × 90%
```

内容过高时保持标题和操作按钮可访问，仅内容区滚动。动态文本、中英文切换和错误提示不得把确认/取消按钮推出可见区域。

## 页面级验收

### Main、Login

- 小屏启动时窗口完整位于可用区域；
- 标题栏和窗口按钮始终可见；
- 登录内容过高时可滚动；
- 登录错误、用户信息和登录按钮不被截断；
- 跨屏和外屏拔出后窗口保持可见。

### Home、Tool

- 卡片按 wide/medium/compact 自动调整列数；
- 卡片内容变窄时增加高度，不缩小字体；
- 页面可滚动到所有卡片和操作项。

### Redmine

- 登录表单 compact 下单列；
- Workspace 双栏 compact 下上下排列或切换；
- Clone 标签和输入框 compact 下上下排列；
- Software Release、Compare Status 等下拉框和必填错误完整可见；
- Clone、取消、提交按钮始终可访问；
- 附件和长 URL 可换行或局部滚动。

### Jira、Jira Audit

- 筛选条件 compact 下纵向排列；
- 多选候选不与输入框互相挤压；
- JQL、关键词和操作按钮可访问；
- 查询结果使用自己的列表/表格滚动；
- Audit 输入、摘要和结果不互相遮挡；
- cache-first 与后台刷新行为不受布局档位切换影响。

### Test Config

- wide 下测试树与参数区双栏；
- compact 下上下排列或使用明确的树/参数视图切换；
- 参数输入、错误提示和开始按钮始终可访问；
- 长路径和多行输入可扩展或局部滚动；
- 不改变 `test_page_state.json` 参数 owner。

### Run、Report

- 步骤、日志、摘要在 compact 下纵向排列；
- 表格和日志保留局部滚动；
- 状态、步骤和操作按钮不被日志区域挤走；
- Report 详情、导出和打开目录操作始终可访问；
- 不改变步骤和报告模型。

### Confluence Audit、Daily Report

- 筛选和操作区可换行或纵向排列；
- 结果表格局部滚动；
- 日期、项目和导出控件不被截断；
- 后台加载时页面结构和缓存内容先显示。

### Settings、Debug

- 设置项 compact 下标签在上、控件在下；
- Debug 多面板 compact 下单列；
- 日志和诊断数据局部滚动；
- 固定宽度输入改为有上下限的弹性宽度。

## 状态持久化边界

保存主窗口宽度、高度、正常窗口位置、最大化状态及用户主动调整的导航栏状态。恢复前必须用当前可用屏幕约束位置和尺寸；上次外屏已移除时回到主屏可见区域。

不保存以下派生状态：

- compact/medium/wide；
- 当前列数；
- 标签上下或左右排列；
- 自动换行结果。

这些状态始终由当前视口宽度实时计算。

默认不保存页面、表单和表格滚动位置，重新进入页面从顶部开始，避免旧屏幕尺寸下的偏移在新屏幕上造成“内容丢失”。确有业务价值的长日志或报告阅读位置继续由原业务 owner 单独决定；本次不新增通用滚动缓存。

## 极端状态与错误处理

- 可用区域暂时为零：使用安全默认尺寸并延迟重算；
- DPI 或屏幕变化：重算窗口边界和布局档位，不手动缩放字体；
- 固有最小宽度超过视口：仅对应表格、日志或代码区域横向滚动；
- 动态文本变长：优先换行、elide 或增加高度；
- 中英文切换：依赖 implicit size 重新布局；
- 后台刷新增加字段或卡片：布局自动重排，不依赖固定高度；
- 保存窗口状态损坏或超界：使用安全默认值，不阻止启动。

## 最低支持与验证矩阵

最低支持窗口可用逻辑尺寸为 `960 × 540`。低于该尺寸仍保证通过滚动访问主要内容，但不承诺所有区域同时可见。

自动与人工验证覆盖：

```text
960 × 540
1024 × 640
1366 × 768
1920 × 1080
```

并覆盖 Windows 100%、125%、150% 缩放，窗口从内屏拖到外屏、拖回内屏以及外屏拔出。

## 测试策略

### 窗口尺寸

- 初始尺寸不超过 `availableGeometry`；
- 大屏正常设计尺寸不被无故缩小；
- 保存尺寸过大时收敛；
- 保存位置在失效外屏时回到主屏；
- 标题栏和窗口按钮保持可见。

### QML 响应式行为

- 向业务页面注入 960、1024、1366、1920 宽度；
- 验证档位、列数、排列方向和滚动 owner；
- 验证关键按钮、输入框和必填错误仍可访问；
- 验证页面及公共业务弹窗 source QML 无 warning；
- 验证中英文切换后无重叠和截断。

### 多显示器人工验收

- 内屏启动；
- 拖到高分辨率外屏；
- 拖回内屏；
- 外屏拔出；
- 100%、125%、150% Windows 缩放；
- 小屏从页面顶部滚动到底部，确认所有输入和操作可达。

验收不要求截图像素完全一致，只要求字体清晰、无重叠、无截断、无不可达操作和错误的嵌套滚动。

## 禁止事项

- 禁止应用级整体 `scale`；
- 禁止按显示器品牌、物理英寸、设备名或某一分辨率写特例；
- 禁止通过减小字体或点击区域解决空间不足；
- 禁止机械地给所有页面叠加嵌套 ScrollView；
- 禁止页面自定义冲突断点；
- 禁止隐藏字段标签、错误提示或操作按钮换取空间；
- 禁止移动业务状态 owner 或建立第二套窗口、页面或滚动状态机制。
