# Redmine 30% 紧凑密度试版设计

## 背景与目标

现有多屏适配已经提供窗口边界约束和部分响应式重排，但 Redmine 页面在较小屏幕或较高 Windows DPI 下仍沿用大屏舒适密度。页面结构本身可用，主要问题是 margin、padding、spacing、固定高度和控件高度占用过多空间，导致 Issue 列表与详情等主体内容可视高度不足。

本试版只验证 Redmine 的紧凑密度效果：在不改变现有页面结构、导航关系和业务行为的前提下，将非内容空间目标压缩 30%，为主体内容释放更多可视区域。

## 范围

本次仅覆盖：

- Tool 页中仅由 Redmine 使用或可按 Redmine 激活状态安全调整的容器留白；
- Redmine workspace 的标题、说明、筛选区、状态区、Issue 列表和详情区间距；
- Redmine 复用的 Issue 浏览与详情组件中明确属于展示密度的尺寸。

本次不覆盖：

- 其他 Tool、Jira、Jira Audit、Confluence、Daily Report、Test、Run、Report 页面；
- 主导航结构、Tool 分组导航结构和左右分栏关系；
- Redmine 查询、认证、筛选、缓存、选择、Clone 和 Jira 创建业务逻辑；
- 全局 QML `scale`、字体整体缩放或 Windows DPI 设置；
- 安装包构建。

## 方案

采用 Redmine 局部密度系数，目标值为 `0.70`。密度只作用于展示尺寸，不作用于业务状态。

### 尺寸分类

1. **按 0.70 缩放**
   - 页面和卡片 margin；
   - frame padding；
   - RowLayout、ColumnLayout、GridLayout spacing；
   - 标题、说明、状态和主体区域之间的垂直间距；
   - 空 Schedule 区域高度；
   - Issue 列表行和详情 section 的装饰性留白。

2. **有最低值的压缩**
   - 按钮和输入框高度；
   - 图标和小型操作按钮；
   - Issue 列表的最小可选中行高；
   - SplitView 左侧列表最小宽度。

   这些尺寸按紧凑密度收缩，但必须保留清晰文字和可靠点击区域。

3. **不按 0.70 缩放**
   - 正文基础字号；
   - 用户、Jira、Redmine 返回的动态文本；
   - 业务数据、状态和选择模型；
   - 主体内容可用高度和宽度。

大标题仅允许使用现有较小的 FluentUI 文本样式替换，不对文字对象应用 `scale`。

## 组件边界

密度值由 Redmine workspace 的展示边界统一提供，子组件读取窄化后的展示属性。不得在不同控件中散落 `0.7`、`7`、`8` 等无归属魔法数，也不得建立第二套业务状态。

若公共 Issue 组件同时被 Jira 等页面复用，密度必须作为显式展示属性传入，默认值保持现有行为；只有 Redmine 调用方启用紧凑密度，避免本试版影响其他页面。

Tool 页公共区域只有在选中 Redmine 时才允许采用试版尺寸。切换到其他工具后恢复现有尺寸。

## 布局行为

- 保留 Tool 分类栏与 Redmine workspace 的现有左右关系；
- 保留 Redmine Issue 列表与详情的现有 SplitView 关系；
- 不新增屏幕、设备、分辨率或账户特例；
- 空 Schedule 区域在 Redmine 激活时压缩 30%，但标题和空状态文字仍完整可见；
- 筛选控件保持当前顺序和宽度策略，只减少垂直占用和内部留白；
- 主体 Issue 区域获得压缩后释放出的全部剩余高度；
- 当窗口确实不足时继续沿用现有响应式重排和滚动机制。

## 验收标准

以用户提供的约 1920×1080 截图场景为主要对比基准：

- Redmine 主体 Issue 区域的可视高度相较当前版本明显增加；
- 页面结构、左右分栏和控件顺序不变；
- 非内容留白目标压缩 30%，允许因控件最低高度产生小幅偏差；
- 正文清晰，按钮、输入框和下拉框仍可正常点击；
- 筛选、搜索、Issue 选择、详情查看和 Clone 入口行为不变；
- 切换到非 Redmine 工具时，不应用 Redmine 试版密度；
- QML 无新增 warning，相关 UI 契约测试通过；
- 重建主程序 QRC，并以源码模式实际启动验证。

## 测试策略

先增加会失败的 UI 契约测试，证明当前版本仍使用宽松尺寸，再实施最小改动使其通过。测试至少覆盖：

- Redmine 激活时使用 `0.70` 密度；
- 非 Redmine 工具保持默认密度；
- 空 Schedule 高度随 Redmine 密度变化；
- 公共 Issue 组件默认行为不变，Redmine 可显式启用紧凑密度；
- 关键按钮和输入控件不低于规定的最小尺寸；
- QRC 包含修改后的 QML。

完成自动检查后，在源码模式启动 SmartTest，进入 Tool/Redmine 页面，对比主体内容区域，并由用户决定是否推广。

## 推广与规则更新

本试版不直接推广到全局。用户确认 Redmine 效果后：

1. 将密度 owner 提升为公共响应式展示契约；
2. 按页面逐步迁移，不一次性修改全部页面；
3. 每个页面先提供可见对比并通过验收，再进入下一个页面；
4. 在 `AGENTS.md` 和 SmartTest UI skill 中补充硬规则：响应式适配必须同时考虑布局重排与视觉密度；禁止全局 `scale`；密度试版必须先在一个代表页面验收后再推广。
