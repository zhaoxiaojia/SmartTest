# SmartTest 页面级状态持久化替换设计

## 背景与目标

当前前端状态机制由 `FrontendStateStore`、`FrontendStateBridge`、`PersistentPage`、`PersistBinding`、`PersistGroup` 及多个 `Persist*` 控件共同完成。该机制把持久化身份、控件生命周期、父级 scope、默认值捕获、恢复保护、用户切换和 debounce 分散到控件实例中。新布局、动态 `Loader`、异步选项或控件重建容易导致缓存被默认值覆盖、恢复触发回写、重复注册以及索引指向错误选项。

本设计用 Qt 官方 `Settings`/`QSettings` 替换现有通用前端 JSON 持久化机制。持久化 owner 从控件实例提升为显式页面状态模型，使布局结构不再参与缓存身份和加载时机。现有 `frontend_state.json` 必须完整迁移；验证成功后删除旧文件，迁移逻辑仅保留在过渡版本中。

## 范围

本次替换当前 `FrontendStateStore` 管理的状态：

- 全局主题、系统标题栏偏好和语言；
- 主窗口状态；
- Jira 页面筛选；
- Tool 页面显示偏好；
- Jira Audit Workspace 中已进入旧前端状态文件的普通输入。

本次不改变以下 owner：

- `T_TestConfig.qml` 测试参数和 `test_page_state.json`；
- 登录凭据、认证状态、密码、API Key 和 Token；
- 测试运行状态、查询结果、日志和报告；
- Jira、Redmine 及其他业务 Bridge 已拥有的业务状态。

实施时若发现旧文件存在本文未定义的 scope 或字段，停止迁移该字段并补充设计，不丢弃、不猜测归属。

## 核心原则

1. 持久化身份属于业务可理解的页面状态，不属于视觉控件或布局树。
2. 页面状态显式声明；不扫描控件、不从 `objectName` 推断 key、不向上查找 scope。
3. 只有明确的用户交互修改持久化状态；程序恢复、联动和默认值修正不保存。
4. 选择项保存稳定业务 ID，不保存 `currentIndex` 或易变显示文本。
5. 异步页面采用缓存优先、后台刷新；失败时保留最后一次可用内容。
6. 用户级状态严格隔离；未登录时不读取、不创建、不写入用户缓存。
7. 每类状态只有一个 owner，不允许新旧机制长期双写。

## 架构

### 页面状态模型

QML 下建立按职责拆分的状态组件，例如：

```text
qml/state/
├── ApplicationState.qml
├── WindowState.qml
├── JiraPageState.qml
├── ToolPageState.qml
└── JiraAuditWorkspaceState.qml
```

每个组件内部直接使用 `import QtCore` 的 `Settings`，显式声明稳定字段、默认值和独立 schema 版本。字段以业务语义命名，例如 `selectedProjectIds`、`selectedBoardId` 和 `advancedExpanded`；禁止 `projectComboIndex`、`leftColumnTextBox` 等布局或控件语义。

页面控件只展示和编辑页面状态，不接触文件、用户命名空间、迁移和通用持久化 API。新控件只有被显式加入页面 schema 后才会持久化；临时输入默认不持久化。

### 命名空间

登录前可用的状态放在全局 category：

```text
global/application
global/window
```

用户页面状态按规范化账号隔离：

```text
users/alice/jira
users/alice/tool
users/bob/jira
users/bob/tool
```

不存在 `users/anonymous/*`。账号规范化由认证 owner 提供，QML 不自行解析域名、大小写或账号格式。

### 登录生命周期

认证状态通过 `Loader` 或等价生命周期 owner 控制用户状态对象：

1. 未登录时不创建用户级 `Settings`，页面使用空的临时状态；
2. 登录完成且规范化账号确定后，创建该账号的页面状态对象；
3. 页面立即渲染该用户缓存；
4. 退出时停止页面业务操作，提交已确认且仍待 debounce 的输入；
5. 销毁用户状态对象并清空可见用户内容；
6. 未登录期间的 UI 操作不写入任何用户 category；
7. 新用户登录时创建新的状态对象，不在同一 `Settings` 实例上动态切换账号。

该生命周期避免旧用户信号在切换过程中写入新用户 category。

## 保存与恢复

页面状态只有 `Loading` 和 `Ready` 两个阶段。加载期间允许展示恢复值，但不接受持久化写入或触发首次业务查询；依赖项解析完成后进入 `Ready`。

保存时机按交互语义定义：

| 状态 | 保存时机 |
|---|---|
| 开关、复选框 | 用户点击后立即保存 |
| 普通选择 | 用户确认选择后立即保存 |
| 单行文本 | `editingFinished` 或短 debounce |
| 多行文本 | 500–1000ms debounce，页面关闭前提交 |
| 窗口位置和尺寸 | debounce 或正常关闭时 |
| 关联筛选 | 页面状态按业务规则一致更新 |
| 程序恢复、默认值修正 | 不保存 |
| 查询结果、进度、错误 | 永不保存 |

文本交互使用 `textEdited` 或 `editingFinished`，不得以可被程序赋值触发的 `textChanged` 作为持久化入口。正常退出时由页面状态统一同步，不为每个控件维护独立 ready、restoring、注册和销毁 flush 状态。

## 异步页面与候选缓存

Jira、Redmine 及后续大量异步页面采用 stale-while-revalidate：

```text
同步读取本地快照
→ 立即渲染页面和用户选择
→ 后台刷新远程候选数据
→ 按稳定 ID 合并
→ 失败时保留旧内容并给出非阻塞提示
```

缓存分为两个 owner：

- 用户选择、筛选和布局偏好由页面级 `Settings` 保存；
- 项目、状态、用户、看板等远程候选快照由对应 Jira/Redmine Bridge 保存和刷新。

候选快照至少包含稳定 ID、显示名称、必要的依赖 ID、缓存版本和最后刷新时间。查询结果列表不纳入本次持久化，每次进入或查询时仍由后台获取。

有缓存时页面不得用全屏 Loading 覆盖内容；只显示小型“正在更新”状态。无缓存时先显示页面布局和本地字段，仅依赖远程数据的局部控件显示加载状态。

### 稳定选择恢复

下拉框保存稳定 ID，不保存索引。恢复顺序为：

1. 从页面状态恢复选择 ID；
2. 立即使用候选快照按 ID 显示；
3. 后台获取最新候选项；
4. 按 ID 合并，不触发用户选择事件和重复保存；
5. 若旧选择暂不在最新结果中，保留为“上次选择，当前不可用”，不静默切换；
6. 只有用户明确选择、明确清除，或业务 owner 确认 ID 永久无效时才改变持久值。

项目、看板、Sprint 等关联选择按声明的依赖顺序恢复。加载下游候选期间不得把中间默认值写回缓存。用户主动改变上游选择时，由页面业务状态明确清理不再适用的下游 ID。

## Schema 与演进

每个状态组件拥有独立 schema 版本，例如 `ApplicationState v1`、`WindowState v1`、`JiraPageState v1`。单个页面演进只迁移该页面，不牵连其他页面和用户。

schema 明确定义字段名、类型、默认值、稳定 ID 语义和废弃规则。无效字段只影响所属页面；回退默认值不立即写回，以保留诊断证据。敏感字段禁止进入页面状态和候选快照。

## 一次性迁移

迁移器枚举旧 `frontend_state.json` 中的全部用户和 scope，而不是只迁移当前登录用户。旧对象字段拆分为新 schema 的显式属性。只有能从旧候选数据可靠解析的索引才转换为稳定 ID；无法证明映射时停止该字段迁移并报告，不凭猜测写入。

迁移严格执行：

```text
Parse → Transform → Write → Sync → Read Back → Verify → Delete
```

具体要求：

1. 完整读取和校验旧 JSON，迁移前不修改源文件；
2. 在内存生成完整迁移清单；
3. 写入 Qt `Settings` 并调用 `sync()`；
4. 检查 `QSettings.status()`；
5. 重新读取所有目标字段，逐项比较类型和值；
6. 只有全部字段验证一致才删除 `frontend_state.json`；
7. 任一步失败均保留旧文件，且旧文件字节不变；
8. 失败时页面可使用默认状态启动，下次启动允许重试；
9. 迁移日志只记录用户 scope、页面 scope、字段名、数量和原因，不记录字段值。

迁移报告至少包含用户数量、读取字段数、迁移字段数、跳过字段数、验证字段数和旧文件删除结果。

### 发布节奏

过渡版本包含新页面状态、一次性迁移器和验证逻辑。旧机制不再作为正常运行路径，只保留读取迁移能力。确认过渡版本已完成用户数据迁移后，后续清理版本删除迁移器、迁移 marker、旧映射和迁移专用测试。迁移脚本不作为长期产品代码保留。

## 旧机制删除边界

页面迁移后不得新旧双写。全部消费者切换并完成迁移验证后删除：

- `FrontendStateStore`；
- `FrontendStateBridge`；
- `PersistentPage`；
- `PersistBinding`、`PersistGroup` 和全部 `Persist*` 控件；
- 对应 QRC 条目和生成资源中的旧内容；
- 旧机制的实现形状测试和废弃兼容路径。

候选缓存不得演变为通用前端状态仓库。Jira、Redmine 等 Bridge 分别拥有自己的远程候选快照、刷新和合并规则。

## 错误处理

- 候选快照损坏：忽略对应快照，局部显示加载状态并后台重取，不影响页面 `Settings`；
- 后台刷新失败：保留旧候选和当前选择，显示非阻塞错误，不清空缓存；
- 页面字段类型无效：只回退该页面字段，不影响其他页面和用户；
- 迁移写入或回读失败：保留完整旧文件，不宣布迁移成功；
- 用户退出：不得把清空后的默认 UI 状态写回原用户缓存。

## 测试与验收

### 页面状态

- 首次启动使用默认值；
- 用户修改后重新创建页面可以恢复；
- 调整布局层级不影响持久化 key；
- 程序恢复不产生保存；
- 未登录状态不读取、不创建、不写入用户缓存；
- Alice 与 Bob 状态完全隔离；
- Alice 退出后页面清空，再登录后恢复 Alice 状态；
- 退出不会把空状态覆盖到原用户缓存。

### 异步候选

- 有缓存、网络成功：先显示缓存，再更新最新数据；
- 有缓存、网络失败：保留缓存并显示非阻塞错误；
- 无缓存、网络成功：仅局部 loading，返回后显示数据；
- 慢响应：页面布局和缓存内容立即可见；
- 选项顺序变化：按 ID 恢复正确选择；
- 旧选择不在最新候选中：保留不可用旧选择，不静默切换；
- 关联下拉框按依赖顺序恢复，不保存中间默认值。

### 迁移

使用包含多用户、全局状态、组合筛选、Unicode、空值、旧类型和损坏字段的代表性 fixture，验证：

- 完整成功才删除旧文件；
- 失败时旧文件字节不变；
- 用户和页面之间无交叉；
- 敏感字段不迁移；
- 字段数量与迁移报告一致；
- 稳定 ID 不退化为索引；
- 第二次运行结果稳定。

### 环境验证

- 页面状态、迁移器和候选缓存聚焦测试；
- `testing/self_tests/ui/test_owned_ui_translations.py`；
- QRC 重建及时效检查；
- 从仓库根目录启动源码版本；
- 两个不同账号人工切换；
- 断网和慢网络启动；
- 准备迁移发布时验证打包版本和真实用户数据目录。

功能验收必须同时满足：新布局无需注册持久化控件；移动、嵌套或替换控件不丢状态；用户隔离和退出清空成立；异步页面首屏优先显示缓存；后台刷新不覆盖有效选择；旧数据完整迁移并删除；旧机制完全移除；不存在新旧双写。

代码质量验收必须确认每类状态只有一个 owner，不存在自动控件扫描、索引持久化、敏感数据、临时兼容残留或不必要抽象，并通过 `git diff --check`。
