# Confluence 审查周期与分组报告设计

## 目标

统一手动与定期审查的周期边界，给“格式有误”提供可追溯的实际响应，并减少 Excel 中重复的公共字段。

## 审查周期

- 手动触发：当前自然周周一 `00:00`（Asia/Shanghai）至实际触发时间。
- 定期触发：当前自然周周一 `00:00` 至周五 `00:00`，即周四 `24:00`。
- 两种触发复用同一审查服务；仅由 `AuditExecutionContext.trigger` 选择周期计算方式。
- 周期结束继续采用左闭右开语义。

## 格式错误追溯

- 每个矩阵结果允许携带非敏感的诊断说明。
- 只有 `invalid_format` 写入报告 `PS`。
- `PS` 按检查项逐行记录：检查项、错误类型、实际响应摘要。
- 实际响应摘要优先保留页面标题、pageId、HTTP/解析错误或候选页面；不写密码、Cookie、Token 和整页 HTML。
- 多个检查项来自同一页面错误时合并同类项，列出受影响检查项，避免重复响应。

## Excel 布局

- 按 `(Support Mode, Project Status)` 分区。
- 每个分区首行写一次：Support Mode、Project Status、审查周期。
- 项目表头为：年份、项目名、项目链接、12 个关注项、PS。
- 项目行不再重复 Support Mode、Project Status、审查周期。
- 年份保留在项目行；跨年项目写 `2025, 2026`，项目只出现一次。
- 分区稳定排序；区内按年份和项目名排序。

## 验收

- 手动和定期周期测试覆盖周中、周五及边界时间。
- 无法读取、页面归属错误、页面缺失等 `invalid_format` 都有 PS。
- Excel 分区、合并同类 PS、超链接和三态值均有持久测试。
- 不启用内容语义审查、PDF 或截图流程。
