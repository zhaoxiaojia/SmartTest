# Confluence 项目周审工具设计

## 1. 目标

在 SmartTest `Common Tools` 下新增面向 M 岗的 Confluence 项目周审工具。工具自动发现全部 A 级且处于开发阶段的项目，对上一自然周的页面变化、QA 任务、测试推进和资料完整性进行混合审查，并保存可追溯证据。

首版由用户点击“立即审查全部项目”触发。周一 09:00 自动调度不在本次范围内；业务确认后再增加独立调度能力。

## 2. 审查范围与周期

- 自动发现带项目状态模板标签的 Status Report 页面，不要求用户输入 URL，也不提供项目勾选。
- 仅审查 `Support Mode = A` 且 `Current Stage = 2 IN DEVELOPMENT` 的项目。
- 排除 POC、Pending、结案、取消和其他阶段。
- 每次重新发现项目，自动纳入新增项目并排除已改变阶段的项目。
- 审查窗口固定为触发时刻所在周的上一自然周：上周一 `00:00:00` 至上周日 `23:59:59`，使用本地 `Asia/Shanghai` 业务时间。
- 周末有效更新合规；本周一 `00:00` 之后的修改属于新周期，不能补算上周。

## 3. 总体方案

采用“静态规则优先、AI 仅处理模糊语义”的混合审查：

1. Confluence 集成层通过 `atlassian-python-api` 复用 Confluence Server REST API，使用当前 SmartTest LDAP 登录账号和瞬时密码。
2. 静态审查层完成项目筛选、页面发现、版本时间、版本差异、链接、任务、日期、附件、占位符和数字关系等确定性判断。
3. AI 审查层复用 `support/ai` 的 OpenAI-compatible 客户端。首版使用当前选中的公网 DeepSeek 模型，审查模块不绑定具体模型 ID。
4. 发送公网模型前仅保留完成审阅所需的最小正文或图片区域，并移除人员姓名、账号、邮箱、内部 URL 查询参数等非必要信息。
5. AI 不可用、未配置或响应无效时保留静态规则结果，模糊项标为“无法判断”，不得把 AI 失败误报为业务不合规。

## 4. 组件与所有权

### `support/confluence_integration/`

正式 Confluence owner，封装认证、CQL 查询、分页、页面详情、历史版本、指定版本正文、子页面和附件。业务层不直接调用第三方客户端。

### `support/confluence_audit/`

拥有业务周期、项目模型、规则、脱敏、AI 语义审查、批次编排、历史存储和 XLSX 导出。规则为静态 Python 代码，不提供前端规则编辑。

### `ui/example/bridge/ConfluenceAuditBridge.py`

复用 `AuthBridge.transientCredential()`，异步运行全量审查，向 QML 暴露一个只读 `viewState`；登录变化时使当前运行结果失效。

### `ConfluenceAuditWorkspace.qml`

只负责总览、进度、项目列表、问题证据、历史批次和导出，不解析 Confluence HTML，不承担业务判断。

## 5. 项目发现

- 首选 CQL 标签入口：`pm-summary` 与 `templatev1`。
- 对候选 Status Report 解析 Project Target 表格中的 `Support Mode`、`Current Stage`、`Project ID`、`Project Space` 和负责人信息。
- 由 `Project Space` 链接定位项目主页，从主页中按规范标题发现目标子页面。
- 标签或项目关系不完整时生成“项目发现信息不完整”结果，不静默忽略。
- 首版不扫描整个 Confluence 空间，避免不可控的性能与权限影响。

## 6. 静态与语义规则

### Project Status Report

- `Status Summary` 必须在上一自然周产生正文差异。
- 纯格式、顺序或空白变化不算业务更新。
- `Key Target and Completeness(Development Stage)` 必须存在 QA 分组和重要节点任务。
- 任务解析描述、负责人、截止日期与勾选状态；到期未完成判不通过，可判断时标记延期完成。
- `XXX`、`XXXX.XX.XX` 等模板占位直接判不通过。
- Highlights 与 Impact issues 有内容时必须包含有效链接；空表必须有明确 `None/N/A/无` 才能判不适用。
- Milestone 日期变化时必须说明变化与延期原因。
- AI 判断新增内容是否属于真实推进，是否包含当前结果或下一步。

### Test Information

- 页面必须存在，且上一自然周必须有实质更新。
- 阶段、版本、平台、测试人和日期不能保留模板值。
- 静态校验 Pass、Fail、Pending、Total、Pass Rate 等数字关系。
- Fail 大于零时必须提供失败摘要和可追踪问题证据。
- Blocking QA Testing Items 与重要测试任务按日期、完成状态和本周变化审查。
- AI 判断测试结果是否形成总结，以及阻塞项是否有实质状态更新。

### Test Plan

- 页面必须存在且不是默认模板。
- QA 计划必须细化到周次或明确日期区间，并包含测试内容与交付目标。
- AI 判断计划是否可执行。

### Test Environment Setup and Precautions

- 页面必须存在。
- 至少覆盖环境搭建步骤、设备或软件、关键配置和常用日志获取方式。
- 首版检查完整性，不要求每周更新。

### Summary of Experience and Typical Cases

- 原需求适用于项目结项。
- 本工具首版只审查开发中项目，因此标为“不适用/结项时检查”，不计为当前违规。

### Test Report Store

- 页面必须存在，并包含测试报告附件或有效报告链接。
- 展示附件名称、上传时间、上传人和版本。
- 是否“定期归档”按上一自然周是否新增报告判定。
- AI 仅在报告标题或嵌入图片无法由规则识别时参与，不默认读取整份报告。

## 7. 结果模型

结果状态统一为：

- `passed`：满足要求。
- `risk`：存在风险但静态证据不足以直接判违规。
- `failed`：明确违反静态或语义规则。
- `not_applicable`：当前阶段不适用。
- `unknown`：外部访问、AI 或结构异常导致无法判断。

每条问题包含项目、页面、规则 ID、严重程度、状态、证据来源、上一周变化摘要、脱敏证据、判定理由、整改建议和可点击页面 URL。批次保存项目数、通过/风险/违规项目数、有效更新数和逐项目结果。

## 8. 前端

- 默认页面：最近一次批次总览。
- 顶部：审查周期、上次执行时间、AI 配置状态、“立即审查全部项目”和“导出 XLSX”。
- 汇总卡：应审、通过、风险、违规项目数及有效更新数。
- 左侧项目列表：按违规、风险、通过、无法判断排序。
- 右侧详情：按页面分组展示规则结果、版本差异摘要、证据、原因、建议和“打开 Confluence”。
- 历史批次：读取本地审查历史，支持切换查看；首版不做趋势图和后台调度。
- 固定界面文本同步维护中英文翻译；外部页面标题、人员、路径和证据保持原文。

## 9. 持久化与敏感信息

- 审查历史保存在 SmartTest 应用数据目录，采用版本化 JSON；只保存审查证据和模型元数据，不保存 LDAP 密码或 AI Key。
- LDAP 密码仅从 `AuthBridge` 瞬时传给后台 worker。
- 日志不得记录密码、AI Key、完整内部正文或未脱敏公网请求。
- 同一页面版本的 AI 结果使用内容哈希缓存，避免重复公网传输。

## 10. 异常与降级

- Confluence 登录失效：终止批次并提示重新 LDAP 登录。
- 单项目或单页面无权限：记录 `unknown` 后继续其他项目。
- 页面结构异常：保留页面 URL 和结构错误证据，不崩溃。
- AI 未配置或失败：静态结果继续，语义项为 `unknown`。
- 用户重复点击：运行中禁用启动按钮；登录改变时忽略旧 worker 返回。

## 11. 验收标准

- 不输入 URL、不勾选项目，一次触发审查全部 A 级开发中项目。
- 周期严格使用上一自然周，周末更新合规，本周一更新不补算上周。
- Confluence 封装位于 `support/`，使用 LDAP 凭据并覆盖分页、版本、正文、子页面和附件。
- 确定性规则不调用 AI；模糊文字或图片才调用可替换 AI 接口。
- 公网请求最小化且脱敏，AI 故障不破坏静态结果。
- 前端可查看进度、批次汇总、项目明细、证据、历史与导出结果。
- 聚焦单元测试、UI 契约测试、真实 Confluence 只读冒烟和源码启动验证通过。
