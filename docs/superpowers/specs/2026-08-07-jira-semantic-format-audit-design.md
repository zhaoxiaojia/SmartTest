# Jira 语义化格式审查设计

## 背景与目标

当前 Jira 审查把固定英文标题、方括号和章节位置当成合格条件，导致内容完整但格式自由的 Jira 被大量误判。审查目标调整为判断信息是否真实存在、是否足以理解和复现问题；标题格式仅用于识别，不再单独阻断。

采用“脚本宽识别 + AI 语义兜底”：确定性常见表达由脚本直接判断，脚本无法确认但全文可能表达了相同语义时交给现有 AI 复核链路。AI 未配置、失败或响应无效时保留脚本初审结果并标记复核状态，不静默放行。

## 规则边界

1. Description 章节标题允许带或不带 `[]`、`【】`，允许中英文常用同义标题、半角或全角标点，允许标题和值同行或换行。
2. 顶层章节只由明确的章节标题切换；Notes 内嵌 Test Case 的普通 `Expected results:` 等文字不得错误结束 Notes。
3. HW/SW 信息不强制位于 Notes，也不强制使用 `HW info` / `SW info`。全文中的硬件信息、机型、平台、尺寸、软件版本、测试版本或构建版本均可作为候选。
4. 脚本只直接放行确定性命中且内容非空的项目；只有标题、空值或下一个已知标题不能算有效内容。
5. 测试步骤、实际结果、预期结果、复现概率、对比信息、Notes、HW 和 SW 等脚本违规，只要全文存在可能相关的自然语言或同义标签，就进入 AI 复核。AI 按语义完整性判断，不按标题格式判断。
6. 明确缺少内容且全文无相关候选语义的项目继续保持不合格，避免所有 Description 无条件进入 AI 或被放行。
7. `SUMMARY.FORMAT` 初审失败但 Summary 非空且包含可供判断的问题描述时，也进入 AI 复核；该复核只判断标题结构和问题描述是否可理解，不判断概率。
8. Summary 为空、Component 为空等客观字段缺失仍由脚本直接拦截，不允许 AI 根据其他字段推断已经填写。
9. 产品决定停止审查 Summary/标题中的复现概率。Summary 只检查 4–6 个分组、分组后的冒号和非空问题描述；标题末尾是否包含百分比、分数、设备数量或文字概率均不影响合格，也不进入 AI。Description 的复现概率章节与格式规则不在本次取消范围内。

## 复用与所有权

- 扩展 `tool/common/jira_format_audit/rules.py` 的现有章节解析、别名和 AI 候选分流，不创建第二套解析器或新的审查流程。
- 复用 `tool/common/jira_format_audit/service.py` 已有的单 Jira 合并 AI 请求、响应校验、失败降级和结果合并机制。
- 只在现有 AI prompt 中补充“按自然语言语义判定、忽略标题装饰和语言”的边界，不改变 AI 客户端、并发或报告模型。
- 净生产代码增长应保持有限，优先扩展现有 owner 和数据表。

## 验收场景

1. SH-31004 等价 Description：Notes 内有嵌套 Test Case 和 `Expected results:`，后续 `HW info: DVT2`、`SW info: V460`，HW/SW 均通过。
2. TV-242738 等价 Description：`【操作步骤】`、`【实际结果】`、`【期望结果】`、`【概率】`、`【软件版本】`、`【硬件信息】` 均被识别为对应语义且不因中文或缺少方括号失败。
3. 英文标题不带方括号、中文标题、全角标点、标题和值换行均通过确定性识别。
4. 自然语言表达了字段语义但脚本无法确定时，该违规项进入 AI 候选；一个 Jira 的多个候选仍只调用一次 AI。
5. Summary 有或没有概率表达均不产生概率违规；`10%`、`（10%）`、`1/6台`、无概率和非标准概率文本都不影响标题合格。
6. Summary 结构或问题描述模糊时仍可由 `SUMMARY.FORMAT` 进入 AI，但不得以概率缺失或概率格式作为失败理由。
7. 空 Summary、空标题、真正缺失、Component 为空、AI 未配置/失败等现有安全降级继续有效。
8. 现有 Jira 规则和服务测试通过，`git diff --check` 通过，无无关文件变化。

## 执行清单

1. 先添加 SH-31004、TV-242738、无方括号标题及自然语言 AI 候选的失败测试并确认 RED。
2. 最小扩展标题归一化、中文别名、全文 HW/SW 识别和 AI 候选分流。
3. 必要时最小调整 AI prompt，保持现有请求与合并契约。
4. 添加 `1/6台` 触发 `SUMMARY.FORMAT` AI 复核以及空 Summary 不进入 AI 的回归测试，不在确定性概率正则中增加单位枚举。
5. 运行聚焦规则/服务测试，再运行 Jira 审查自测集合、编译检查和 `git diff --check`。
6. 清理探索性测试、临时诊断和重复机制，由 Atlas 做 diff-led 验收。
7. 删除 `SUMMARY.PROBABILITY` 活跃规则及其 AI 候选路径，更新 Summary 格式文案和耐久测试；保留 Description 概率审查。

## 非目标

- 不修改 Jira 原始数据访问、UI、导出格式、AI 客户端配置或其他 Common Tool。
- 不把格式建议新增为另一套阻断规则。
- 不针对 Issue Key 写特例。
