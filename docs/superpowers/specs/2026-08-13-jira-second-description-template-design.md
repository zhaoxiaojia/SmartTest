# Jira 第二套 Description 模板审查设计

## 目标

在现有 Jira 格式审查中支持项目认可的第二套 Description 三列表格模板，同时保持 Summary、Component、报告生成、AI 复核和其他既有行为不变。

第二套模板以表头 `模块 | 需要填写信息 | 测试信息` 识别。表头后的每一行均要求第三列“测试信息”非空；`无`、`-` 及其他非空文本均为有效值。第三列为空或仅包含空白字符时，该行判错，并在审查结果中指出对应的第二列字段名。一次审查应报告全部空值行。

## 所有权与流程

继续由 `tool/common/jira_format_audit/rules.py` 负责 Description 解析和校验，不新增审查服务、入口、状态、传输或报告链路。

现有 `audit_issue()` 调用关系保持不变：

1. Summary 继续执行现有规则。
2. Component 继续执行现有规则。
3. Description 在现有 `_audit_description()` 边界内识别模板并选择规则：
   - 匹配第二套三列表格表头时，执行第三列非空校验；
   - 未匹配时，执行现有第一套章节模板规则。
4. 违规项继续进入现有 `IssueAuditResult`、报表导出和界面展示流程。

第二套模板的缺失值属于确定性格式错误，不进入 AI 语义复核。

## 表格解析与错误行为

解析仅服务于 Description 的模板识别和行校验，并兼容 Jira 返回的现有文本表格表示。识别必须依赖完整的三个表头名称，避免普通文本或第一套模板被误判。

数据行处理规则：

- 跳过表头行。
- 第一列允许因 Jira 合并单元格表现为空。
- 第二列用于定位和展示错误字段。
- 第三列使用去除首尾空白后的值判断是否为空。
- `无` 和 `-` 不做特殊否定处理，按普通非空值通过。
- 收集全部第三列空值行；每个空值行生成可定位的 Description 违规信息。
- 无法识别为第二套模板时不猜测，继续执行第一套规则。

## 测试与验收

采用现有 `testing/self_tests/tool/test_jira_format_audit_rules.py` 做测试驱动开发，至少覆盖：

- 完整第二套模板通过，且 Summary 和 Component 仍按原规则执行。
- 第三列为 `无` 或 `-` 时通过。
- 一个第三列为空时，报告对应第二列字段名。
- 多个第三列为空时，一次报告全部对应行。
- 第三列只有空白时判错。
- 第一列为空的合并单元格续行仍正常校验。
- 第一套 Description 模板继续执行原有规则。
- 非表格文本不会被误识别为第二套模板。

验证执行聚焦 pytest、相关 Jira 审查测试、Python 编译检查和 `git diff --check`。不要求访问真实 Jira 写入，也不改变 TV-241053。
